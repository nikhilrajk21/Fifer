# Fifer project rules

- Project root: this workspace. Fifer is independent of Expedia Lite. Never copy or modify Expedia Lite files or create a nested Fifer folder.
- This is a coursework prototype only. Use fictional scenarios and never real distress disclosures.
- Do not diagnose, claim therapeutic effectiveness, or imply human monitoring.
- Keep crisis access independent of any model or classifier. Do not automatically call or message emergency services.
- Keep the 5-4-3-2-1 skill sequence controlled by the application, not invented by a model.
- Keep user control, Stop/Leave, Pause, and Emergency Support available.
- Planned stack: Vue with JavaScript → FastAPI with Python → SQLite, running locally on localhost.
- Use Figma or Figma Make for the Part 3.1 mockup. Record actual design evidence and clearly label proposed work.
- Before adding dependencies: CHECK the need, compatibility, and security; TAKE ACTION only within the approved scope; VERIFY the result and record evidence.
- Never place credentials in frontend code, reports, screenshots, prompts, or Git. Use ignored local environment files when configuration is eventually needed.
- Report actual evidence only. Never invent research, citations, test results, screenshots, or completion claims.
- Current scope: starter documentation and folders only. Do not implement application code, install dependencies, create a database, or add real crisis phone numbers or emergency-contact integrations.
- Do not commit or push until the user approves the proposed commit scope.
